# 实时性能

v0.2.1 针对击键到显示之间的等待，以及每帧重复的绘制与编码工作进行了优化。分辨率保持 1680×960，和声确认时间、颜色历史、音符衰减和踏板虚化规则保持原有行为。

- MIDI 消息逐条按顺序处理，同一批消息合并为一次立即刷新。25 毫秒动画时钟继续更新衰减，不再让新击键等待它。
- 新击键和布局设置立即提交 OBS；连续衰减动画仍限制为约每秒 30 次。工作线程最多处理一个正在出图的快照和一个最新待处理快照。
- 浏览器保持一个有界长轮询，完成的新帧会唤醒请求，最长等待一秒；无客户端时跳过无用出图，重连会主动提交当前状态。
- 缓存调号、谱号、音高排布、静态琴键几何和画笔；键床按实际 DPI 缓存，音符及高亮仍按输出分辨率绘制。透明背景和柔光在复用的像素缓冲区中合成。
- PNG 采用 Up 行过滤与快速 DEFLATE，保留预乘透明像素的往返结果。编码器和图像缓冲区均复用，像素循环在严格校验尺寸、stride 和长度后执行。

## 本机比较

2026-09-06，同一 Windows 电脑依次运行 v0.2.0 发布程序集与优化后的发布程序集，均为 x64、`/optimize+`。每场景预热 5 帧、测量 20 帧，持续改变音符亮度、颜色和和声历史值；透明底、氛围强度 12%，1680×960 输出。

| 场景 | v0.2.0 平均出图 | v0.2.1 平均出图 | 降低 |
| --- | ---: | ---: | ---: |
| 8 个实按音 | 101.60 ms | 55.27 ms | 46% |
| 8 个踏板延留音 | 147.70 ms | 96.88 ms | 34% |
| 8 音混合，含踏板延留 | 136.85 ms | 95.26 ms | 30% |
| 88 音密集压力场景 | 240.51 ms | 215.25 ms | 11% |

这些数字包含准备、栅格化、背景合成与 PNG 编码，不包含 MIDI 驱动、浏览器解码和 OBS 展示。它们不是端到端延迟或固定帧率保证；大量延留音的栅格化仍较贵。快速 PNG 会用稍大的数据换取编码速度，无氛围的测试帧约增大 25%，本机输出不经过互联网。

另外删除了原链路上 25 / 33 / 33 毫秒三个周期采样点的等待。这个周期之和表示可能的额外等待上限，不能当作实测整体延迟的降低量。独立服务测试中，已发布帧到本地长轮询完成的 5 次样本中位为 0.538 毫秒。

## 复现与回归

```powershell
.\build.ps1 -OutputDirectory artifacts\staging-performance
.\tests\MeasureObsPerformance.ps1 -AssemblyPath artifacts\staging-performance\NoteView.exe -Label current
.\tests\TestFastPng.ps1
.\tests\TestScheduling.ps1
.\tests\TestObsIntegration.ps1
.\tests\TestStaffPerformance.ps1 -Label regression-only
```

比较不同版本时，为每个程序集使用不同的 Label，串行运行并保持其它负载尽量一致。CSV 和对应场景 PNG 位于 `artifacts\performance-<Label>`。像素、透明边角、清空终态、最小化、重连、和声历史及静态音符位置另有功能回归。

升级后在 OBS 浏览器源属性中刷新一次页面，才能让已打开的来源加载新的长轮询逻辑。
